# Bug Bounty Tracking System

A Streamlit application backed by SQLite for tracking security researchers, application assets, reported vulnerabilities, patches, bounty payouts, and provenance/audit history.

## Features

- View database metrics and the current vulnerability and asset records.
- Search vulnerabilities by title and sort them by severity score.
- Track vulnerability status, severity, reporting date, affected asset, and reporting hacker.
- Review bounty payout records.
- Inspect audit logs generated by SQLite triggers for vulnerability and bounty changes.
- Maintain the administrator responsible for database changes through the `CurrentUser` table.

## Project structure

| File | Description |
| --- | --- |
| `app.py` | Streamlit user interface and database queries |
| `database.py` | Recreates `database.db` from `schema.sql` |
| `schema.sql` | SQLite schema, seed data, triggers, and sample updates |
| `queries.sql` | Example provenance and reporting queries |
| `database.db` | SQLite database used by the application |

## Requirements

- Python 3.9 or newer
- Streamlit
- Pandas

Install the Python dependencies with:

```bash
pip install streamlit pandas
```

## Getting started

1. Clone the repository and open the project directory.
2. Recreate the SQLite database from the schema and seed data:

   ```bash
   python database.py
   ```

3. Start the Streamlit application:

   ```bash
   streamlit run app.py
   ```

4. Open the local URL shown by Streamlit, usually `http://localhost:8501`.

Running `database.py` deletes and recreates `database.db`, so use it when a fresh sample dataset is needed.

## Application sections

### Database Overview

Displays record counts for hackers, assets, vulnerabilities, and bounty payouts, followed by the vulnerability and asset tables.

### Vulnerability Tracker

Lists vulnerabilities with their associated hacker and asset, severity information, status, and report date. Use the search box to filter by title and view the severity chart.

### Provenance & Audit Logs

Displays vulnerability and bounty audit records created by the triggers in `schema.sql`. These records capture inserts and updates, including the previous value, new value, timestamp, and administrator username.

## Database model

The database includes tables for `Hackers`, `Admins`, `Assets`, `Vulnerabilities`, `Patches`, `BountyPayouts`, `CurrentUser`, `Audit_Vulnerabilities`, and `Audit_BountyPayouts`. Foreign keys and `CHECK` constraints enforce relationships and valid severity, status, and criticality values.

## Example SQL

The queries in `queries.sql` demonstrate how to:

- Explain vulnerability changes through audit history.
- Trace status changes over time.
- Combine vulnerability and bounty audit events.
- Calculate average elapsed time from reporting to an audit event.
- Query bounty changes within a date range.
